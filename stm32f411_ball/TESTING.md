# MOTER 烧录后测试手册（H题 要求4 摆杆稳球）

固件已验证：0 错误 0 警告，25.80KB（MDK-Lite 32KB 限制内）。
控制方案：**滑模 PD + 回零偏学习 + 静摩擦脱困脉冲 + 车加速度前馈**
（移植自成熟参考工程 MSPM0G3507 ball_balance，符号已适配本机机械约定）。
按下面 6 个阶段从静到动逐级测试，**每个阶段通过再进下一个**。

---

## 阶段 0：上电前检查清单

| 检查项 | 标准 |
|---|---|
| 驱动器细分拨码 | 与 `stepper.h` 的 `STEPPER_STEPS_PER_REV=1600` 一致（1.8°电机×8细分） |
| 接线 | EN1=PB0、DIR1=PB1、ST1=PA8（脉冲）、共地 |
| MaixCam | A19(TX) → PA10(RX)，**与 STM32 共地** |
| 串口调试 | USB-TTL：TTL_RX ← PA9（只看不发），115200 8N1 |
| 摆杆机械 | 上电前目视调平（上电位置 = 水平零位） |
| 上电顺序 | **先开 MaixCam**（等它完成摆杆标定约 10s）再短按 PA0 |

唯一按键 = **PA0**（按下接地，内部上拉；**接到 3.3V 侧无效**）：
- **短按** = 启动稳球闭环（先点头 3° 确认，回平后自动启动）
- **运行中短按** = 点头 2° 示意"任务在跑"（比赛时不要按，会轻微扰动球）
- **运行中长按 1 秒** = 停止并回平
- 长按停止后摆杆自动小点头示意，短按可重新启动

## 阶段 1：上电自检（不接 MaixCam，只接 USB-TTL 看 PA9）

**操作**：上电，看串口。

**预期**：
```
============================================
[STEPPER] MOTER / STM32F411RET6 ready
[TASK ] H题 要求4：滑模PD+前馈 行驶稳球（误差<=1cm）
...
[TEST ] 上电1秒摆杆自动点头 = 脉冲链路自检
        再短按PA0有第二次点头 = 按键也正常
============================================
[SELFTEST] 摆杆点头自检：能动 = 使能+脉冲链路正常      ← 上电约 1 秒时摆杆自动点头
[IDLE] en_pin=1 key_raw=1 key=0 busy=0 fr=0 ce=0      ← 待机每 1 秒一行
```
- 电机上电后轴有保持力矩（手拧感觉有阻力）
- **上电约 1 秒：摆杆自动"点头"一次**（抬 3° 再回平）——这是自检，
  不用按键就能确认使能+脉冲链路是通的
- **短按 PA0：摆杆再"点头"一次**，然后才启动稳球闭环——第二次点头
  就是按键起效的肉眼确认
- 串口同步打印：`[MISSION] 按键确认：摆杆点头...` → `[MISSION] 要求4 启动：稳球闭环开启`
- 没接 MaixCam 时（fr=0）提示"摆杆先保持水平，球回视野自动开始稳球"——
  **新固件丢球不再退出任务**：保持最后指令 600ms 后摆杆以 12°/s 缓慢回平，
  任务一直在跑，球回视野立即自动恢复稳球。长按 1 秒才真正停止。

**"两次点头"判定树**（不接串口也能定位问题在哪一环）：

| 上电1秒自检点头 | 按PA0点头 | 结论 |
|---|---|---|
| 有 | 有 | **全部正常**，进阶段 2 |
| 有 | 无 | **按键链路问题**（脉冲链路已被自检证明是通的）：① 万用表量 PA0：未按≈3.3V、按住≈0V，不满足 = 按键没接对；② 按键必须是**常开**型接 **PA0↔GND**（接到 3.3V 侧永远无效，输入是上拉）；③ 拿杜邦线把 PA0 直接碰一下 GND：点头 = 按键坏/接错，不点头 = PA0 引脚或焊盘问题（少见） |
| 无 | — | **脉冲链路问题**（注意：保持力矩≠脉冲有效！）：查 PA8(STEP)→驱动器 PUL 接线与共地；3.3V 推不动驱动器光耦时改**共阳接法**（PUL+ 接驱动器 5V，PUL- 接 PA8），或查驱动器脉冲输入是否需要 5V 电平 |
| 无 | 有 | 理论矛盾，不可能出现（按键点头也要走同一条脉冲链路） |

**`[IDLE]` 心跳逐项解读（排查"没力矩/按键没反应"就靠它）**：

| 字段 | 正常值 | 异常时的含义 |
|---|---|---|
| `en_pin` | **1** | 0 = 固件没把 PB0 拉高（固件问题）；1 但仍没力矩 → 问题在**驱动器侧**（EN 极性反/没共地/供电没开） |
| `key_raw` | **1**（未按时上拉高） | 0 = PA0 被拉地（按键粘住/接错到 VCC）；**按下时应变 0**，不变 → 按键没接在 PA0↔GND 之间 |
| `key` | 未按=0，按住=1 | `key_raw` 变了但 `key` 不变 → 消抖 20ms 未到或接线抖动 |
| `busy` | 0（静止时） | 1 = 步进还在斜坡运行 |
| `fr` / `ce` | 0（不接 MaixCam 时） | 接了 MaixCam 后 fr 每 500ms 约涨 25；不涨 = 视觉链路问题 |

**不正常**：无横幅 → 查 TX/RX 是否接反、波特率、供电；连横幅都没有说明固件没跑起来（查烧录是否成功、BOOT0 是否接地）。

## 阶段 2：电机方向与手动角度（台架，发 M 命令）

> M/Z 命令要发进 PA10。MaixCam 也在往 PA10 发数据会打架，
> **这一阶段先断开 MaixCam 的 TX 线**，USB-TTL 的 TX 接 PA10。
> （方向标定只需做一次。新固件丢球不退出任务，短按启动后可以
> **从容地**发 M 命令，不用担心 1.5 秒窗口。）

**操作**：
1. PA0 短按启动（没接视觉也没关系，摆杆保持水平等待）
2. 发 `M,2000`（回车换行结尾）
3. 观察摆杆，**画面左端（+x 端）应抬高约 2°**
4. 发 `M,-2000` 应反向抬 2°；发 `M,0` 退出手动；手动限幅 ±14°
5. 长按 PA0 一秒 → 摆杆应平滑回到水平位

**不正常**：
- 抬的是画面**右**端 → `ball_ctrl.h` 里 `ROD_DIR_SIGN` 改 `-1.0f`，重新编译
  （**必须先做对这步**：整个控制律都建立在"+角抬高画面左端"的约定上）
- 完全不动 → 查使能/脉冲线；串口发 `M,2000` 应看到电机微动
- 抖/嗡嗡响不转 → `stepper.h` 的 `STEPPER_ACCEL` 降到 8000

## 阶段 3：视觉链路（接回 MaixCam TX）

**操作**：
1. 断开 USB-TTL 的 TX（PA10 只留给 MaixCam），PA9 仍接 USB-TTL 看
2. 上电 MaixCam，等约 10 秒（它要 5s 瞄准 + 5s 标定摆杆）
3. PA0 短按启动
4. 手指拨球慢慢滚，看串口 `[RUN]` 行

**预期**：
```
[RUN] x=+35.2 v=+60mm/s c=87 ref=+0.0 | fb=+850 ff=+0 cmd=+0.9deg acc=+0 sat=0 ok=1 cal=1 fr=1523 ce=0 pos=+2
```
- `fr`（合法帧数）持续增长，每 500ms 约增 25（50Hz×0.5s）
- `ce`（校验错帧数）基本不涨
- `cal`（MaixCam 摆杆标定完成标志）= **1**。`ok=0` 但 `fr` 在涨 → 先看 `cal`：
  `cal=0` 说明还没标定完，等它标完自动恢复
- `v` 是 MCU 自己差分测速的结果（不再用相机速度字段）
- 球向**画面左**滚 → `x` 增大、`v` 为正（同号，正确）
- 球移出视野 → `ok=0`，600ms 内摆杆保持；继续丢 → 12°/s 缓慢回平（任务不退出）；
  球回视野 → `ok=1` 且发 `W0`

**不正常**：
- `fr` 不涨 → A19/PA10 接反、没共地、波特率
- `ce` 疯狂涨 → 线太长/受干扰，缩短线、查共地
- `x` 乱跳 → 视觉固定曝光没关、反光干扰（查 MaixCam 端标定）

**斜视角警告**：
程序只在画面高度 24%~72% 的水平条带内找球（本工程已加宽）。摄像头斜装时
摆杆斜穿画面，两端伸出条带 = 球一滚到端部就"消失"。**用 web UI 检查**：
满摆幅（±14°）时摆杆两端都必须留在两条红线之间；仍出头就继续调大
`roi_top_ratio` / `roi_bottom_ratio`。更彻底的办法：把摄像头摆正对，让
摆杆在画面里水平居中（参考设计的设计假设，前端识别最稳）。

## 阶段 4：静止闭环稳球（核心指标预演）

**操作**：接好视觉，球放中心 O，PA0 短按启动，等 0.4s 启动稳定窗过去。

**预期**：
- 球偏离中心会被**拉回**并在中心附近稳住
- 远端（偏离 >40mm）摆杆允许到 ±14° 大幅回正，近端收窄 ±10° 防过冲
  ——即"**先大幅回正、再微调**"
- 把球推到 +5cm 处松手，应约 1~2 秒内被拉回（要求3 的 5s 指标余量充足）
- `x` 稳定后 |x| < 3mm 左右；`cmd` 幅度小（一般 <1°）
- 球被摩擦顶住不动时：约 200ms 后摆杆开始发**脱困脉冲**（斜坡-保持-卸力，
  近端从 4.5° 逐脉冲加宽到 5°、远端从 3° 加宽到 9°），球一动立即收力
- 球稳定停在偏离中心处不回：约 150ms 后**回零偏学习**启动，偏置角缓慢
  积累（≤±3°），几十秒内把稳态偏差顶回中心（替代旧积分项）

**整定**（参数都在 `ball_ctrl.h`，改完重新编译）：
| 现象 | 处理 |
|---|---|
| 回中太慢 | 加 `BALL_PD_KP_MDEG_PER_MM`（220 → 300），或加大 `BALL_RETURN_MAX_MDEG`（14000 → 16000） |
| 回中过冲/来回振荡 | 加 `BALL_PD_KD_MDEG_PER_MM_S`（50 → 80）或减 KP |
| 稳态停偏，偏置学习救不回 | 确认 `BALL_BIAS_*` 参数没被改小；机械零太歪就先停机调平再发 `Z` |
| 球粘住不动、脉冲推不开 | 加大 `BALL_STICK_NEAR_BOOST`（4500 → 5500）与 `BALL_STICK_NEAR_MAX` |
| 稳定球摆杆小幅抖 | 加大 `BALL_TARGET_DEADBAND`（120 → 200） |
| `sat=1` 频繁出现 | 反馈项在撞 ±10°/±14° 限幅——球被放太远或 KP 太大 |
| 启动瞬间猛摆 | 确认 `BALL_ENABLE_SETTLE_MS=400` 生效（ MaixCam 标定完成前本就不出力） |

**注意**：回零偏学习消除的是"控制器坐标里"的偏差——球会回到 MaixCam
认定的 x=0（或 `R` 设定的目标）处。若球稳定停的位置**明显不在摆杆物理
中点**，是视觉中点标定问题，调 MaixCam 端的 `center_trim_cm`（或运行中发
`R,<x0.1mm>` 改目标位置，要求6 就用这条）。

## 阶段 5：加速度前馈验证（模拟车加减速）

**操作**（同阶段 2 需要发命令，断开视觉 TX 或用 1k 电阻共线）：
1. PA0 短按启动（手动 M 优先；或球在中心让闭环自己稳）
2. 发 `A,500` = 模拟车沿 +x 方向（画面左）以 0.5m/s² 加速
3. 观察摆杆：**画面左端（+x 端）应放低约 2.8°**（正前馈 = 负角度，
   抵消球被惯性甩向画面右的趋势）
4. 发 `A,0` 回平；发 `A,-500` 反向验证
5. 方向反了 → `ball_ctrl.h` 的 `BALL_INERTIA_DIRECTION` 从 `-1` 改 `+1`；
   幅度不对 → 调 `BALL_INERTIA_MM_S2_PER_DEG`（180，越小前馈越强）

**实车替代方案**：没接车主控前，可以**手持小车沿摆杆方向前后晃**模拟
加减速，看球是否基本不滚（`x` 漂移小）；或直接让车主控发 `A` 帧。

## 阶段 6：上车联调（要求4 完整流程）

**操作**：
1. 摆杆调平 → 上电 → 开 MaixCam 等标定 → 球放中心 O
2. 短按 PA0（串口打 `[MISSION] 要求4 启动`）
3. 小车启动，沿黑线顺时针从 A 驶向 B（AB≤8s 由车主控保证）
4. 全程盯串口 `[RUN]` 的 `x`，或赛后看图传录像回放

**合格标准**：行驶全程 `|x| ≤ 10`（即 ±1cm），`ok=1` 不中断。

**不正常速查**：
| 现象 | 原因/处理 |
|---|---|
| 起步瞬间球后滚明显 | 前馈没起作用：车主控没发 A 帧 → 接 A 帧，确认 `BALL_INERTIA_DIRECTION` 方向正确 |
| 过弯时球往外甩 | 要求4 直线段没这问题；进弯前车主控应提前减速 |
| 行驶中摆杆慢慢回平 | 丢球 >600ms：查 `ce` 是否暴涨、摄像头是否被振动移位；球回视野会自动恢复，`[RUN]` 里 `ok` 变 1 即恢复 |
| 直线行驶 x 缓慢偏向一侧 | 偏置学习会自己顶回来；等不及就停机调平后发 `Z`，或调 MaixCam 的 `center_trim_cm` |
| 球在后端粘住不动 | 脱困脉冲上限不够 → 加大 `BALL_STICK_TRA_MAX`（9000 → 11000）；仍不行查视觉条带是否盖住端部 |

## 附：丢球行为（会自动发生，不是故障）

| 状况 | 行为 |
|---|---|
| 链路断（fr 不再增长 >150ms） | 立即进入回平：12°/s 缓慢回水平，发 `W2`（若曾锁定过球） |
| 相机在发帧但丢检出 ≤600ms | **保持最后指令**（球短暂出视野摆杆不乱动），发 `W1` 建议车主控减速 |
| 丢检出 >600ms | 12°/s 缓慢回平，清滤波/偏置，**任务保持运行不退出** |
| 重新捕获 | 发 `W0`，位置滤波在新位置种入，从当前角限速平滑恢复稳球 |
| 一帧位置跳变 >4cm | 可疑帧丢弃，连续 3 帧确认才算真重捕获 |

**与旧固件的差别**：旧版丢球 1.5s 直接回平退出任务（要重按 PA0）；
新版**永不因丢球退出**，最坏情况就是回平待球，球一进视野立即恢复——
赛场上不会被一次遮挡打断任务。

## 附：调完参数的保存顺序

所有可调参数集中在 `ball_ctrl.h`（PD/偏置/脉冲/限幅/置信度/超时）和
`stepper.h`（速度/加速度/细分）。**比赛前把现场调好的值写死进代码再编译一次**，
避免现场临时改错。
