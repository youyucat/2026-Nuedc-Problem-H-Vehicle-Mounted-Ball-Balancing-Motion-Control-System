# ctrl_v2 —— 摆杆稳球控制（从零重写版）

不依赖任何 HAL 的纯 C 实现，PC 与目标平台共用同一份源码。

## 为什么重写

旧实现（`Core/Src/ball_ctrl.c`，1027 行、约 50 个全局状态）在台架上的表现是
**静摩擦卡顿 + 过冲持续振荡**。诊断结论：这是**延迟导致的极限环**，不是参数没调好。

回路延迟约 50~70 ms（视觉 20 ms 出帧 + 传输 + 控制 10 ms + 步进斜率限幅 60°/s）。
对双积分器来说，延迟的伤害是平方级的：

- 增益调大 → 相位裕度不足 → 过冲振荡
- 增益调小 → 推不动 → 静摩擦卡住 → 靠大脉冲猛踢 → 又过冲

**这个结构本身没有稳定余量**，所以调参永远收敛不了。旧实现已打 tag `legacy-ball-ctrl` 保留。

## 本版做了什么不同的事

| 做法 | 说明 |
| --- | --- |
| **延迟补偿** | 状态前推 `x + v·Td + ½a·Td²`，用「动作真正生效的时刻」做反馈 |
| **执行器可达性** | 输出始终过斜率限幅，控制器知道自己要的是够不到的角度 |
| **静摩擦管理** | 不是加大增益硬推，而是「准静止判定 → 最小可信脉冲 → 球一动立即卸力」 |
| **纯函数式状态** | 所有状态在 `ball_v2_t` 里，`reset` 一次 `memset`，不存在漏字段 |

## 仿真验证（PC）

```bash
cd Core/ctrl_v2/sim
make                                      # 需要宿主 gcc
./sim_ctrl 40                             # 初始偏移 40mm，用默认参数
./sim_ctrl 40 30 20 50 200 180 8          # x0 kp kd delay pulse gain a_break
make sweep                                # 10/25/40/60mm 四点扫描
```

### 模型（2026-10-25 按实测重写）

早期模型的三个参数全是错的，因为它们建立在「角度虚高 15 倍」之上：

| 项 | 旧（错误） | 现（实测） | 依据 |
| --- | --- | --- | --- |
| 视觉帧周期 | 20 ms | **34.5 ms** | 实测 29 fps |
| 位置量化 | 0.1 mm | **0.64 mm** | 480x360 下 1 px |
| 回路延迟 | 40 ms | **50 ms** | 等帧 17 + 检测 24.5 + 串口 1 + 控制 5 |
| 静摩擦阈值 | 400 mm/s²（≈2.2°） | **8 mm/s²（≈0.044°）** | 标定后重算，见下 |
| 执行器 | 瞬间到位 | **36°/s 斜率限幅** | 2400pps ÷ 66.67 步/度 |
| 滚动阻力 | 30 mm/s² | 10 mm/s² | 钢球滚动阻力系数 0.001~0.002 |

**静摩擦阈值为什么从 400 降到 8**：早期 T1 扫描时命令 1° 实际只倾 0.067°，
球就能从静止滚动 → 真实阈值 < 0.067°×180 ≈ 12 mm/s²。原来「需要 5~7.5°
脱困脉冲」的结论，本质是在用错误角度硬顶一个并不存在的静摩擦。

### 整定结果

**kp=30 / kd=30 / 脉冲 0.6° 起（自适应 +0.5°）/ 懒区 4mm**

| 初始偏移 | 反向过冲 | 进入 ±10mm | 终值误差 | 达标 |
| --- | --- | --- | --- | --- |
| 10 mm | 0.78 mm | 498 ms | −0.78 mm | 是 |
| 15 mm | 0.00 mm | 545 ms | 1.86 mm | 是 |
| 25 mm | 1.05 mm | 785 ms | −1.05 mm | 是 |
| 40 mm | 0.00 mm | 1373 ms | 3.16 mm | 是 |
| 60 mm | 0.00 mm | 1668 ms | 1.78 mm | 是 |

40/60 mm 的终值偏大是因为「懒区」——刻意不动手，留 3 mm 余差换安静。
指标 10 mm，仍在范围内。

### 四个反直觉的结论（2026-10-25 实机验证后修订）

**① kd 的上限是 30：太小不刹车，太大放大噪声**

- 太小：实测静摩擦阈值 **1.0°**。球以 30 mm/s 冲过来时 kd=20 只给 0.6°，
  扣掉摩擦后**净加速度仍朝外** —— 刹车命令等于没下。这就是「到中点停不住、
  反复冲过去」的直接原因。
- 太大：位置量化 0.64 mm、帧间隔 34.5 ms，两点差分测速噪声 18.6 mm/s。
  kd=60 会把它放大成 1.1° 的角度抖动，仿真里直接发散。

**30 是「够刹车」与「不放大噪声」的交点。** 想用更大的 kd，必须先改测速算法
（多帧最小二乘，而不是两点差分）。

**② 脱困脉冲的关键是「时长」，不是「幅值」**

| 脉冲持续 | 效果 |
| --- | --- |
| 300 ms（早期） | 球被加速到 54 mm/s、冲出去 8 mm 以上 |
| **100 ms（现在）** | 20ms 爬升 + 30ms 保持 + 50ms 卸力，给个初速度就收 |

1° 倾角维持 300 ms 的冲量，本来就该把球推出去很远。缩短到 100 ms 后
过冲从 8~14 mm 降到 3~5 mm。

**③ 小误差时必须「懒」，否则会把刚稳住的球一脚踢飞（实机最大坑）**

球稳在 ±1.8 mm 时：P 项只有 `30×1.8/10 = 5.4 mdeg = 0.054°`，远小于 1° 阈值，
**球确实推不动** → 状态机判成「卡住」→ 发 0.645° 脉冲 + 攒到 0.6° 偏置
→ 合力 1.3° 把球踢到 ±15 mm。

日志铁证：`x=-1.8mm` 时输出 `-1.251°`，而 P 项最多只能算出 0.05°。

修复：新增懒区 `stick_deadband_01mm = 40`（4 mm）。误差小于它时
**完全不介入**——不发脉冲、不学偏置、清零自适应累加、已攒的偏置缓慢泄放。

| 初始偏移 | 修复前 | 修复后 |
| --- | --- | --- |
| 1.8 mm | 安静 | 安静（峰值 108 mdeg）|
| 2.5 mm | **7.9 s 后突然 −1.28°，球被踢走** | 安静（峰值 75 mdeg）|
| 3.5 mm | 安静 | 安静（峰值 231 mdeg）|
| 4.5 mm | 触发脉冲 | 正常触发，收到 0.53 mm |
| 40 mm | 过冲 5.53 mm | **过冲 0 mm** |

代价：稳态余差可能留在 4 mm 以内。收益：不会再自己把球踢飞。指标是 ±10 mm，
留 2.5 倍余量，这笔交易划算。

**意外收益**：大偏移的过冲反而从 4~5 mm 降到 0~1 mm —— 因为接近目标时
不再多余地踢。

**④ 执行器滞后与视觉延迟同量级**

36°/s 意味着摆到 5° 要 **139 ms**，比视觉链路延迟（50 ms）还大。
所以控制带宽的真正瓶颈是步进速度，不是算法。若后续要提高响应，
优先提 `STEPPER_SERVO_SPEED`（2400 → 4000pps ≈ 60°/s），并确认不丢步。

### 鲁棒性（含懒区）

4 个初始偏移 × 3 档延迟(40/50/70ms) × 3 档 gain(122/180/250) 共 **36 组，
全部达标（±10 mm）**，过冲 ≤1.05 mm。

## 标定结论：电机轴到摆杆 15:1 机械减速

2026-10-25 水平仪标定（命令角 25/40/55/70/85 度 → 读数 1/2/3/4/5 度）：

| 命令角 | 真实倾角(拟合) | 水平仪读数 |
| --- | --- | --- |
| 25° | 1.67° | 1 |
| 40° | 2.67° | 2 |
| 55° | 3.67° | 3 |
| 70° | 4.67° | 4 |
| 85° | 5.67° | 5 |

五点严格落在 `真实角 = 命令角 / 15` 上。读数系统性偏小 0.67 度，
是水平仪整数截断造成的，**不是机械死区**（44 步的间隙不符合物理）。

结论：`STEPPER_GEAR_RATIO = 15`，摆杆真实 1 度 = 1600/360×15 ≈ **66.67 步**。
摆杆分辨率由 0.225°/步 提高到 **0.015°/步**。

连带影响：所有以 mdeg 为单位的控制参数（KP/KD/限幅/脱困脉冲/偏置）
都是在「以为 5 度、实际 0.33 度」的错误角度下整定的，修正后实际力度
变成 15 倍，**全部失效**。旧 PD 闭环因此暂停使用，等 ctrl_v2 接入。

## 自检固件：标定复核

`selftest.c` / `selftest.h`，默认关闭（`BALL_SELFTEST_ENABLE = 0`，完全不编译进固件）。

修正后命令角即摆杆真实倾角，自检用来**复核标定是否正确**：
每档发 N 度，水平仪应读到 N 度。

### 接入（改 3 处代码 + 加 1 个文件）

1. `selftest.h`：`#define BALL_SELFTEST_ENABLE (1)`
2. `Core/Src/main.c` `stepper_enable(1);` 之后加：
   ```c
   #if BALL_SELFTEST_ENABLE
     selftest_init();
   #endif
   ```
3. `Core/Src/main.c` 主循环 1ms 任务块内、`stepper_tick_1ms();` 之后加：
   ```c
   #if BALL_SELFTEST_ENABLE
       selftest_poll();
   #endif
   ```
4. Keil 工程里 Add Existing Files：`Core/ctrl_v2/selftest.c`

### 测试流程

上电后自动扫 5 档：**1 / 2 / 3 / 4 / 5 度（真实倾角）**。
每档节奏：摆到位 1s → **保持 4 秒（读水平仪）** → 回平 1.5s → 下一档。
前置静置 5 秒，全程约 37 秒。

因为角度正好是整数，无论水平仪是截断还是四舍五入，都应该读到
**1/2/3/4/5**。读到其他值说明标定还有问题。

### 串口输出格式

| 行 | 含义 |
| --- | --- |
| `#` | 注释/提示，含「现在读水平仪」的提示 |
| `R,<档号>,<命令mdeg>,<步进位置>,<球位置>,<忙>` | 每档保持结束时的数据 |
| `# DONE` | 结束，摆杆已回平 |

步进位置应约为 67/133/200/267/333 步，可用来交叉核对。

### 注意

- **建议先把钢球拿走**，1~5 度会让球缓慢滚到端点
- 上电前必须目视调平摆杆，上电那一刻的位置就是零位
- 别按 KEY1，旧 PD 增益已失效，启动闭环会过冲
- 跑完把开关改回 0 再编译正常固件
