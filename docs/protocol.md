# 串口协议

本文件只记录**实际存在**的串口链路。术语统一为三个名字，避免再用 A/B 缩写：

| 名字 | 硬件 | 负责 | 目录 |
| --- | --- | --- | --- |
| **循迹板** | MSPM0G3507 | 灰度循迹、双直流电机 | `mspm0_line_follow/` |
| **滚球板** | STM32F411 | 摆杆步进、小球位置闭环 | `stm32f411_ball/` |
| **摄像头** | MaixCam | 拍钢球位置，发二进制帧 | `vision/maixcam/` |

> 状态：**已定稿**。修改前双方确认。

## 1. 决策：循迹板与滚球板不做电气互联

**结论：两块 MCU 之间不接任何信号线，各自完全独立运行。**

原先设计过「循迹板把车体加速度发给滚球板做前馈」，经评估后取消，理由：

| 理由 | 说明 |
| --- | --- |
| 物理上本来就接不通 | 滚球板的 UART1 唯一接收脚已被摄像头占用，见第 3 节 |
| 收益有限 | 前馈只补偿加减速造成的球体惯性扰动；把车开稳能拿到大部分收益 |
| 降低耦合 | 两块板互不依赖，任一块死机不影响另一块；也不用跨板联合调试 |
| 少一个故障点 | 不必新增 UART 驱动、不必改 SysConfig 引脚、不必改视觉脚本转发 |

**代价**：加减速时小球会被惯性甩动，只能靠「把车开得平稳」来压制，
控制上没有任何跨板补偿。量化影响见第 2 节。

滚球板侧原实现的前馈代码（`BALL_INERTIA_*`、`A` 帧解析）**保留不删**，
只是永远收不到输入，`s_accel` 恒为 0，前馈输出恒为 0，等效不存在。
哪天要恢复，接上线即可，不用改代码。

## 2. 「车开得稳」是球稳的唯一保障

既然不做前馈，循迹板的加减速品质直接决定小球能不能稳在 1 cm 内。
本工程相关参数（`mspm0_line_follow/config/template_config.h`）：

| 参数 | 当前值 | 换算 |
| --- | --- | --- |
| `TEMPLATE_LINE_RAMP_STEP_MM_S_PER_TICK` | 1 mm/s / 5 ms | **200 mm/s²** |
| `TEMPLATE_STARTUP_HOLD_MS` | 1000 ms | 上电后静止 1 s 才起步 |
| `TEMPLATE_LINE_MAX_SPEED_MM_S` | 700 mm/s | 上限 |
| `TEMPLATE_LINE_TURN_DECEL_FRACTION` | 10 | 转弯减速 |
| `TEMPLATE_LINE_TURN_MIN_RUN_MM_S` | 80 mm/s | 转弯最低速 |

### 稳态偏移估算（重要）

滚球板经验映射 **1° 倾角 ≈ 180 mm/s²** 的车体加速度，PD 增益 `KP = 0.22°/mm`。
循迹板以 200 mm/s² 匀加速时：

```
等效倾角 = 200 / 180 ≈ 1.1°
稳态球偏移 = 1.1 / 0.22 ≈ 5 mm
```

指标是 ≤ 10 mm，**余量约一半**。因此：

- **`RAMP_STEP` 保持 1，不要为了跑快调到 2 以上。** 调到 2 → 等效 2.2° → 球偏 10 mm，正好卡在指标线上。
- 速度上限 700 mm/s 不建议再提；越快留给纠偏的时间越少。
- 转弯减速比 10 意味着进弯时速度变化率很大，**弯道半径尽量做大**，
  或者把减速做成渐变而不是阶跃。

## 3. 唯一的串口链路：摄像头 → 滚球板

### 物理层

| 项目 | 取值 | 来源 |
| --- | --- | --- |
| 方向 | 摄像头 → 滚球板，单向 | — |
| 摄像头侧引脚 | `A19 = UART1_TX`，`A18 = UART1_RX`（RX 未使用） | `vision/maixcam` |
| 摄像头侧设备 | `/dev/ttyS1` | `CONFIG["uart_device"]` |
| 滚球板侧 | `UART1`，`huart1` | `stm32f411_ball/Core/Src/main.c` |
| 波特率 | 115200，8N1 | 两边一致 |
| 周期 | 20 ms（50 Hz） | `CONFIG["uart_period_ms"]` |

**滚球板的 UART1 接收脚已被摄像头独占**，这是第 1 节决策的直接原因。

### 帧格式（12 字节，小端）

| 字节 | 内容 |
| --- | --- |
| 0-1 | 帧头 `0xAA 0x55` |
| 2 | 类型 = `1` |
| 3 | 序号 0→255 循环 |
| 4 | 标志位：bit0 检测到球 / bit1 管道已标定 / bit2 滤波器有历史 |
| 5-6 | 球位置 int16，**0.1 mm**，画面左为正 |
| 7-8 | 球速度 int16，mm/s（仅遥测，固件不用） |
| 9 | 置信度 0~100 |
| 10-11 | CRC16-CCITT（`0x1021`/`0xFFFF`），覆盖字节 0~9，**低字节在前** |

滚球板不采信相机速度字段，自己用「位置 2 帧差分 ÷ 实测帧周期」算，
因为相机上报的速度偏小。视觉侧细节见 `vision/maixcam/README.md`。

## 4. ASCII 行接口：触摸定点（已接线）+ 调试命令（不接线）

滚球板的解析器同时支持 ASCII 行帧。**自 2026-10-25 起 `R` 帧正式接线**：
MaixCam 屏幕上点一下选定点位置，发 `R,<x0.1mm>` 给滚球板，
实现自定义定点（目标不再固定在中点）。

**R 帧通路（唯一在用的 ASCII 帧）**：

```
MaixCam 触摸屏 ──> 换算(与球位置同公式：center−x，左正右负) ──>
"R,<x0.1mm>\r\n" ──> UART1 ──> 滚球板 ball_ctrl_feed_xref()
```

- 限幅：MaixCam 端夹 ±1200（±120mm），STM32 端再夹 ±ROD_HALF_LEN_MM=120mm
- 校验：`*HH` 可选，触摸定点发送的是**无校验**行
- 目标更新后，ctrl_v2 的懒区/偏置学习自动围绕新目标工作
  （`err_pred = x_pred − xref`），固件无需任何改动
- 调试口 PC6/PC7 同样可发 `R,`（同一解析环），台架上无需触摸屏即可定点
- MaixCam 端开关：`CONFIG["target_touch_enable"]`（False 回固定中点）

其余 ASCII 帧（台架调试用，**不接线**）：

```
<tag>,<f1>[,<f2>][,<f3>][*HH]\n
```

| tag | 含义 | 字段 |
| --- | --- | --- |
| `A` | 车体纵向加速度 | mm/s²，限幅 ±1500（**已废弃，见第 1 节**） |
| `M` | 台架手动摆角 | mdeg |
| `Z` | 水平基准清零 | 无 |
| `B` | 球状态（ASCII 等价） | x, v, conf |

规则：`*HH` 为星号前所有字节 XOR（可选）；`\r` 忽略；行内出现 `< 0x20`
或 `> 0x7E` 的字节则整行作废（防止二进制视觉帧被误认）；上行 24 字节。
